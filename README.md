# 家庭支出（household_expenses）

Home Assistant 自定义集成：把房贷、车贷、消费贷、租赁房屋、出租房屋、租赁车位、出租车位、物业费、取暖费这九类经常性收支，换算成**每日 / 每月 / 每年**金额，每个费用项生成一个传感器实体（状态 = 剩余金额，属性带当月合计、当年合计与日 / 月 / 年明细）。

- 版本 **1.0.7**，最低 Home Assistant **2025.1.0**
- `iot_class: calculated` —— 纯本地计算，不联网，不依赖任何云服务
- 数据来源只有两处：你在集成选项里录入的期间与金额，以及（贷款类）每月还款日推算

---

## 一、安装

### 1. 前置条件

- Home Assistant 2025.1.0 或更高
- 能访问 HA 的配置目录（`/config`，Samba / SSH / 文件编辑器任一方式）

### 2. 方式 A：手动安装（通用，推荐）

1. 下载本仓库，把整个 `household_expenses` 文件夹放进配置目录的 `custom_components` 下：

   ```
   /config/custom_components/household_expenses/
   ├── __init__.py
   ├── calc.py
   ├── config_flow.py
   ├── const.py
   ├── coordinator.py
   ├── sensor.py
   ├── storage.py
   ├── manifest.json
   ├── strings.json
   ├── translations/
   │   ├── en.json
   │   └── zh-Hans.json
   └── brand/            # 集成图标（icon.png / dark_icon.png）
   ```

   > 目录名必须是 `household_expenses`（与 `manifest.json` 里的 `domain` 一致），改名会导致集成加载失败。

2. **重启 Home Assistant**：设置 → 系统 → 右上角 ⋮ → 重启 Home Assistant。

3. **添加集成**：设置 → 设备与服务 → 右下角「+ 添加集成」→ 搜索「**家庭支出**」→ 打开后**无需填写任何内容**，直接提交即可。

   > 只允许添加一次；已添加过会提示「家庭支出已添加，如需增删改费用项请点击集成卡片上的『配置』」。

4. 添加成功后会出现一台设备「家庭支出」。此时还没有任何实体 —— 因为还没录入费用项，接着看第二节。

### 3. 方式 B：HACS 自定义仓库安装

1. HACS → 集成 → 右上角 ⋮ → **自定义存储库**
2. 仓库地址填本项目的 GitHub 地址，类别选「集成」，添加
3. 在 HACS 里搜索「家庭支出」→ 下载 → **重启 Home Assistant**
4. 之后同方式 A 的第 3、4 步

### 4. 在仪表盘上显示（可选）

集成本身只提供实体，用任意卡片（实体卡、统计图、ApexCharts…）都能读。若已安装「消逝卡」前端包（xiaoshi），它会自动带上本集成的配套卡片，直接在仪表盘添加即可：

```yaml
# 完整的家庭支出卡片：表头 + 日历 / 日图表 / 月图表 / 饼图
type: custom:xiaoshi-household-expenses
```

```yaml
# 入口按钮：只显示一枚小按钮，点击弹出上面那张卡片
type: custom:xiaoshi-household-expenses-button
emoji: 💰️
entry_text: 家庭
entities:                     # 按钮与弹出的卡片共用这一份配置
  mortgage: sensor.household_expenses_mortgage_xxxxxxxx
  electric: sensor.state_grid_xxxxxxxxxxxx
```

## 二、增删改费用项

**入口**：设置 → 设备与服务 → 找到「家庭支出」→ 点集成卡片上的「**配置**」。

打开后是主菜单，四个选项：

| 菜单 | 作用 |
| --- | --- |
| 增加费用项 | 新增一项收支（选类型 → 名称 → 期间与金额 → 其他参数） |
| 修改费用项 | 改名、改期间与金额、改其他参数 |
| 删除费用项 | 删除某一项（需二次确认） |
| 完成并保存 | **落库入口**，见下方提示 |

> ⚠️ **所有增删改都是先改草稿，点「完成并保存」才真正写入**（Home Assistant 选项流强制以这一步收尾）。只点「返回」或直接关掉窗口，改动不会生效。

### 1. 增加费用项

1. 主菜单选「**增加费用项**」→ 选择**费用类型**（九选一，见第 4 小节表格）→ 提交
2. 填**名称**：默认是类型名（如「房贷」），可以改。同一类型可以录多项（比如两笔房贷），**名称不能重复**，重复会提示「该名称已存在，请换一个名称」。
3. **录入期间**（这一步决定金额怎么摊）：
   - **开始日期**：必填，格式 `YYYY-MM-DD`
   - **结束日期**：可留空 = 长期（无结束日期）
   - **金额**：字段名随类型变化 —— 贷款是「每月还款金额」、租赁/车位是「每月租赁 / 每月出租金额」、物业费是「每月金额」、取暖费是「**期间总金额**」
   - 金额变过（例如利率调整、涨租）→ 勾选「**再录一段期间（金额变化时用）**」，会再出现一张同样的表单继续录；不勾就直接进入下一步
   - 校验：结束日期不能早于开始日期
4. **其他参数**（按类型自动出现）：

   | 费用类型 | 需要填的其他参数 |
   | --- | --- |
   | 房贷 / 车贷 / 消费贷 | 首付款金额、贷款期间（个月）、剩余金额、还款日（1–31 号）、剩余金额日期 |
   | 租赁房屋 / 出租房屋 | 中介费 |
   | 租赁车位 / 出租车位 | 保管费 |
   | 物业费 | 缴纳截止月份（`YYYY-MM`） |
   | 取暖费 | 无 |

5. 回到主菜单 → 点「**完成并保存**」。实体立刻生成（`sensor.household_expenses_xxx`）。

### 2. 修改费用项

1. 主菜单选「**修改费用项**」→ 在列表里选择要改的那一项（列表按名称显示）
2. 进入子菜单，按需操作，**每次回到这个子菜单改动就已写回草稿**：

   | 子菜单 | 说明 |
   | --- | --- |
   | 修改名称 | 改名，同样不允许与其它项重名 |
   | 管理期间与金额 | 进二级菜单：增加期间 / 修改期间 / 删除期间 |
   | 修改其他参数 | 改首付款、贷款期间、剩余金额、还款日、中介费、缴纳截止月份等 |
   | 返回 | 回到主菜单 |

3. **管理期间与金额**（增 / 改 / 删）：
   - **增加期间**：与新增时的表单一致，适合「下个月起金额变了」的场景
   - **修改期间**：选择一段期间后改日期或金额
   - **删除期间**：**至少要保留一段期间**，删最后一段会提示「至少要保留一段期间」
4. 改完点「**完成并保存**」，集成会自动重载并把实体刷新成新值。

### 3. 删除费用项

1. 主菜单选「**删除费用项**」→ 选择要删的项
2. 在「确认删除」页**勾选「确认删除」**→ 提交（不勾选不会执行）
3. 回到主菜单点「**完成并保存**」→ 该实体及其历史名下的属性一并移除
4. 快照文件（`household_expenses.json`，见第五节）会在下一次刷新时同步更新

### 4. 九种费用类型一览

| 类型 | 名称 | 方向 | 期间金额字段 | 特殊参数 |
| --- | --- | --- | --- | --- |
| `mortgage` | 房贷 | 支出 | 每月还款金额 | 首付款、贷款期间、剩余金额、还款日 |
| `car_loan` | 车贷 | 支出 | 每月还款金额 | 首付款、贷款期间、剩余金额、还款日 |
| `consumer_loan` | 消费贷 | 支出 | 每月还款金额 | 首付款、贷款期间、剩余金额、还款日 |
| `rent_home` | 租赁房屋 | 支出 | 每月租赁金额 | 中介费 |
| `sublet_home` | 出租房屋 | **收入** | 每月出租金额 | 中介费 |
| `rent_parking` | 租赁车位 | 支出 | 每月租赁金额 | 保管费 |
| `sublet_parking` | 出租车位 | **收入** | 每月出租金额 | 保管费 |
| `property_fee` | 物业费 | 支出 | 每月金额 | 缴纳截止月份 |
| `heating_fee` | 取暖费 | 支出 | **期间总金额**（按天摊） | 无 |

> 名称只是显示用，你可以把「房贷」改成「学区房贷款」之类，不影响计算口径。

## 三、计算口径速查

- **每月金额**：该月适用的期间金额（整月落在期间内时取原值；期间只覆盖部分月份时，按日摊到「月」再合计）
- **每日金额**：每月金额 ÷ 当月天数；**取暖费例外** —— 期间内录的是总金额，按 `总金额 ÷ 期间天数` 逐日摊分后再按月合计
- **一次性项**（首付款 / 中介费 / 保管费）：按摊销期间均摊成月度金额 —— 贷款类摊在「贷款期间」上，其余类型摊在各段期间本身
- **剩余金额**：
  - 贷款类：`0 − 当前欠款本金`（负数表示欠款）。当前欠款 = 录入的剩余金额 − **剩余金额日期之后**已经到过的每个还款日的月供；基准日当天不算
  - 物业费：已交金额（至缴纳截止月份）− 应缴金额（至当前月），未交为负
  - 其余类型：`0`
- **明细覆盖范围**：`monthlist` / `yearlist` 一律按「首段期间起点 ~ 末段期间终点」**全量生成**（含还没到来的计划期），**降序**（最近的一期在前）
- **四类不出日明细**：房贷 / 车贷 / 消费贷 / 物业费的 `daylist` 恒为空数组，每日金额由前端按「月金额 ÷ 当月天数」现算 —— 这是为了把实体属性挡在 16384 字节的 Recorder 上限之内

## 四、实体与属性

- **实体 ID**：`sensor.household_expenses_<ascii 标识>`（标识由集成生成并保存在配置里，所以**改名不会改变实体 ID**）
- **状态值**：剩余金额（元，保留 2 位小数）
- **属性**（顺序固定）：

| 属性 | 含义 |
| --- | --- |
| 类型 | `支出` / `收入` |
| 剩余金额 | 见第三节口径 |
| date | 快照生成时间 |
| daylist | 日明细，`[{day, dayCost1, dayCost2}]`，降序；四类贷款/物业费为空数组 |
| monthlist | 月明细，`[{month, monthCost1, monthCost2}]`，降序 |
| yearlist | 年明细，`[{year, yearCost1, yearCost2}]`，降序 |
| 数据源 | 预留字段（当前为空串） |
| 最后同步日期 | 最近一次计算时间 |
| 当月合计 | 当前自然月的合计（主项 + 一次性项） |
| 当年合计 | 当前自然年的合计 |
| 还款日 | 仅贷款类，每月扣款日号 |
| 下次还款日 | 仅贷款类，下一个还款日 `YYYY-MM-DD` |

- **快照文件**：每次刷新（默认 **30 分钟**一次）会把全量结果原子写入 `<config>/household_expenses.json`，结构与实体属性一致，方便外部脚本直接读取。

## 五、常见问题

**Q：为什么有些实体没有历史记录 / 属性只看到「剩余金额」？**
`daylist`、`monthlist`、`yearlist` 数量很大（20 年房贷约 17 KB），会超过 Recorder 单条属性 16384 字节的上限，导致整份属性被丢弃。集成已用 `_unrecorded_attributes` 把这三个列表排除在历史库之外 —— 前端读 `hass.states` 仍然拿得到，只是不落库。历史库里保留的是「剩余金额」等小字段。

**Q：改了费用项的名称，实体名为什么没变？**
实体 ID 用的是配置里保存的 ASCII 标识（`object_id`），刻意不跟随名称走，避免改名后历史数据断档；显示名会随名称更新。

**Q：剩余金额什么时候会自动减少？**
只有贷款类会动，且必须同时配了**还款日**和**剩余金额日期**。每到一个还款日就扣掉当期月供，扣到 0 为止；基准日当天视为已含在余额里，不重复扣。未配置还款日或基准日时保持录入值不变。

**Q：`end` 留空（长期）会算到什么时候？**
用「贷款期间（月）」从首段起点往后推算；仍推算不出（例如物业费没填结束日期）就算到今天。同时有硬顶保护，误填 2999 年之类的日期不会把属性撑爆。

**Q：可以录两笔房贷吗？**
可以。同名不行，改一下名称即可（例如「自住房贷」「车贷-妻」）。
